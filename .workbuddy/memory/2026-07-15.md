用户要求先不动代码，给出 5 个系统配置接口实现方案。已与用户确认决策：

### 已确认决策
- `PUT /api/system/configs` 入参为 `List<SysConfigDTO>`，按 `configKey` 批量 upsert
- `PUT /api/system/dicts/{id}` 锁定 `typeCode/itemCode` 不可改，仅更新 `itemValue/sortOrder/status`
- `GET /configs` 与 `/dicts` 不翻页，直接返回 `List`

### 计划落地文件
- common-module/dto: `SysConfigDTO.java`, `SysDictDTO.java`（带 Create/Update 校验分组）
- backend: `SystemController`(@RequestMapping("/api/system"))、`SystemService`+impl、`SysConfigMapper`/`SysDictMapper`(BaseMapper)、`SysConfigConverter`/`SysDictConverter`
- 实体 `SysConfig`/`SysDict` 与 init.sql 表结构已存在，无需改动

### 实现硬约束（沿用项目约定）
1. 手动 set createdAt/updatedAt（自动填充已坏）
2. 字典新增校验 (type_code,item_code) 唯一→冲突抛 ErrorCode.CONFLICT；按 id 更新查不到抛 NOT_FOUND
3. 系统配置接口加 ADMIN 鉴权（拦截器只认登录不认角色）
4. @PostMapping/@PutMapping 被 OperationLogAspect 自动记日志
5. 返回 ApiResponse<List<...>>，字典按 sortOrder 升序

### 环境踩坑
